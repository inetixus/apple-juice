[x] 3. Bridge / MCP endpoint auth audit
    DONE. Findings:
    - /api/mcp/enqueue + /api/mcp/poll (VPS-facing): Bearer AJ_BRIDGE_SECRET +
      valid session + server-side tool allowlist. Solid.
    - /api/mcp/next + /api/mcp/result (plugin-facing): were session-key only.
      HARDENED: added IP + session rate limits (checkRateLimit), a 256KB cap on
      /result payloads (the agent trusts that data), and a JSON-parse guard.
    - mcp-bridge: added MAX_QUEUE_LEN=50 bound so a runaway producer can't grow
      the per-session queue unbounded. Everything stays per-session + 120s TTL.
    RESIDUAL RISK (follow-up, not blocking): session keys are weak as a sole
    credential — createSessionKey() is randomBytes(4) = 32 bits, and the CLI
    pairing path uses a short authCode AS the key. Fine for read-only status, but
    /result injects data the agent acts on. Recommend: widen session keys to
    >=128 bits for the dashboard path, keep the short human code only for initial
    pairing, then issue a long key. Tracked as task 3b below.

[ ] 3b. Strengthen session-key entropy
