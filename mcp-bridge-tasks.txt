# 🧃 Apple Juice — Custom MCP Bridge (Studio over a polling channel)

## THE GOAL
Replace the one-shot snapshot→diff agent with a TRUE MCP setup:
kiro-cli (MCP client) ⇄ our MCP server (on VPS) ⇄ Studio plugin (over poll bridge)
The model makes real interactive tool calls: read_script → edit → run_playtest →
read errors → fix, each round-tripping into the user's live Studio session.

## ARCHITECTURE
```
 kiro-cli (MCP client, --mcp config)
        │  stdio (MCP protocol)
        ▼
 aj-studio-mcp  (our MCP server, Node, on the VPS)   ← NEW
   tools: studio_get_tree, studio_read_script, studio_write_script,
          studio_create_instance, studio_delete, studio_rename, studio_move,
          studio_run_playtest, studio_get_logs
        │  each tool: enqueue request -> wait for plugin result
        ▼
 Bridge store (per-session command queue + result map)   ← NEW (Redis or in-proc)
        ▲  HTTP long-poll
        │
 Studio plugin  (executes the command, returns result)   ← EXTEND existing plugin
```
